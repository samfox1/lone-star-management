# Review findings — 2026-09-03 (`/code-review high`)

Scope: 35 commits ahead of `origin/dev` (the SEO/GEO and merch/Shopify work) plus the
uncommitted multi-page bridge changes.

**ALL FINDINGS ARE NOW FIXED.** 13 and 14 were in the multi-page work (see
SITE_PAGES_PLAN.md, "P1 shipped"); the rest were in already-shipped SEO/GEO and merch code
and were fixed the same day, test-first, each guard mutation-checked. The descriptions
below are kept AS FILED — they are the record of what was wrong and why, which is worth
more than a list of tick marks. What each fix actually did is in the commit.

Two were found by one agent inside another's work, which is the argument for doing this in
parallel rather than in sequence:
- the new DB-backed publish tests silently broke `tests/mutation-config.test.ts`;
- the M8 fix only worked halfway — `saveSeoField` stopped eating line breaks on the way
  IN, but `faqEntries` (`packages/site-bridge/src/seo.ts`) collapsed them again on the way
  OUT, so `/faqsheet` would still have shown one run-on line and the fix would have looked
  broken from the only place anyone looks.

Three gaps are deliberately NOT closed, and are stated here rather than quietly dropped:
- **DNS rebinding** against H1. Pinning the socket to a checked IP needs a custom undici
  dispatcher and the fetcher is injected. The redirect chain IS re-checked on every hop,
  which closes the easy version.
- **No rate limiter** on the merch route (half of M1). Slug validation landed; the
  negative cache from H3 bounds the upstream cost of a flood instead.
- `saveSeoField`'s server gate still accepts any `ABOUT_PLACEMENTS` member (M9). It
  cannot do better — the manifest is announced at runtime over the bridge and stored
  nowhere, so no server call can consult it. The two panels are the real enforcement
  point, and a value that slips past is inert.

One more thing worth knowing, because it is not in any finding: the H1 host guard would
have SILENTLY DEMOTED FTBK to a template site — its `custom_site_url` is
`http://localhost:3004` in the live DB. There is now an explicit `allowLoopback` option,
opened only in `NODE_ENV=development` and only for the value handed to the BROWSER (the
308, the editor iframe), never for the server fetch. It opens loopback and nothing else.

## High

**H1 · SSRF in the live SEO check** — `src/lib/seo-audit.ts:89`.
`auditLiveSite` server-fetches `custom_site_url`, which is validated only as
`^https?://host…` (`src/lib/custom-site.ts:31`), then follows up to 10 `<loc>` URLs out of
the returned sitemap with no same-origin check — only `!== base`. A manager pointing
`custom_site_url` at `http://169.254.169.254/` and pressing Run check makes the server
issue those requests, and it is NOT blind: response fragments come back to the browser via
`auditSeo`'s `tag.slice(0, 80)` and `result.sitemap.urls`. Entry point `actions.ts:578`.
**Fix:** a host allowlist on `custom_site_url` (reject private/link-local/loopback ranges),
and a same-origin filter on every sitemap URL before it is fetched.

**H2 · `published_at` is queried and then dropped** — `src/lib/site.ts:192`.
The `revisions` query destructures `publishedAt`, but the payload object never includes it
even though `PublicSitePayload.published_at` exists and the SQL door emits it. On a custom
site the editor posts this payload over `init-data`, so `lastModifiedFrom` falls back to
tour dates and the preview's `dateModified` / sitemap `lastmod` disagree with the live
site — the exact drift that function's own comments were written to prevent.

**H3 · The merch price route amplifies a Shopify outage** — `src/app/api/merch/[slug]/route.ts:51`.
`liveMerchForSlug` throws on error and `unstable_cache` stores nothing on a rejection, so
once a store's Storefront cost bucket empties EVERY visitor request re-runs the
service-role RPC plus up to 4 Shopify POSTs (`maxRetries: 3`, 1s backoff). 1k req/min
becomes ~4k+ upstream calls/min and holds the bucket empty. The header's "at most one
upstream call per minute per store" is true only on the success path. **Fix:** cache a
negative result for a short TTL.

## Medium

- **M1** `route.ts:47` — no rate limit and no slug validation, and the slug is the cache
  key, so every distinct slug is a guaranteed miss: one service-role RPC each, and an
  unbounded number of Next data-cache entries. (The token itself is safe —
  `assertShopDomain` pins `*.myshopify.com`.)
- **M2** `seo-audit.ts:93` — `bio-visible` false failure. `visibleText` strips HTML
  entities to a space but `needle` is the raw bio, so a bio containing an apostrophe
  (React emits `&#x27;`) never matches and the audit reports the bio invisible on a page
  rendering it fully. `tests/seo-live-audit.test.ts:42` passes only because its fixture bio
  has no apostrophe.
- **M3** `packages/site-bridge/src/seo.ts:291` — an uploaded video can never produce a
  `VideoObject`: `videoNode` rejects on `!uploadDate`, and `uploadDate = v.published_at` is
  only ever written by the YouTube sync (`src/lib/youtube.ts:155`).
- **M4** `packages/site-bridge/src/seo.ts:458` — the "/edit is noindex" rule PASSES when
  the fetch fails. `text()` returns null for any non-2xx or thrown fetch, and `auditSeo`
  skips on null. One 429 renders the check green while `/edit` is live and indexable.
- **M5** `supabase/migrations/20260826130000_media_kind_default_photo.sql:5` — the
  `kind = 'photo'` backfill marks every artist's media dirty. `kind` joined
  `PUBLISHABLE.media.snapshot` in the same PR, so earlier revisions carry no `kind` and
  `sameSnapshot` counts every row edited. A manager who published yesterday sees a dirty
  badge on every photo.
- **M6** `supabase/migrations/20260826160000_artist_seo_facts.sql:9` — same shape for the
  profile singleton: `schema_type` defaults to `'MusicGroup'` and is in `ARTIST_SNAPSHOT`,
  so `p.edited = 1` permanently until someone republishes.
- **M7** `merch/actions.ts:60` — `await syncShopifyMerch(...)` discards the `SyncResult`,
  and this PR added `merch_handle_uniq`, which makes per-row insert failures newly
  reachable. Reconnect to a different store while old rows hold the handles and every
  colliding insert fails into `errors[]` while the manager reads "Merch pulled".
- **M8** `src/lib/site-editor/save.ts:165` — `saveSeoField` collapses whitespace, which was
  right for one-line `<head>` strings and is wrong now that it gates `faq_answer_1..5`,
  edited in a textarea. A two-paragraph answer saves as one run-on line, and
  `sections/ai.tsx:59` keeps the raw draft in local state so the loss only shows on reload.
- **M9** `tools/seo/sections/about.tsx:47` — the SEO page offers the full
  `ABOUT_PLACEMENTS` registry while `site-tools.tsx:135` filters it to what the manifest
  declares. On a site declaring only `home`, picking "Its own page" saves, the bio vanishes
  from the homepage after publish, and no `/about` route exists. No error anywhere.

## Low

- **L1** `src/lib/merch/shopify.ts:153` — `PAGE_SIZES.variants = 50` truncates silently and
  `available` is derived over the truncated list (`live.ts:50`). A 5×12 garment has 60
  variants; if the first 50 are sold out the site renders sold out on something Shopify
  will sell. `getProducts` pages products but never pages variants.
