# Brand colours — the short version

_Sam, 2026-09-17: "when the artist onboards they select their brand colours. They can choose
multiple, and if it's super light maybe we add a warning. This can also be updated in the
brand page of manager tools."_

That is the whole feature. Keep it that size.

- **Where they are set:** one onboarding step, and a fifth row on the Brand page beside
  Primary logo, Secondary logo, Tab icon and Fonts. Same row grammar, same `ColorPalette`
  control used everywhere else.
- **What is stored:** an ordered list of hexes on the artist. First is primary, second is
  secondary. A handful, not a mood board.
- **The warning:** if a colour is too light to read on white, say so and carry on. It stays
  a colour; it just stops being used for text. (Skeen's cyan is the live case.)
- **Why artist-level:** today the editor's swatches come from the SITE's declared palette,
  so the colours a manager reaches for live in a website's code. A brand outlives any one
  website.

**Not for the landing page.** That stays black and white (Sam, same day); the only colour
there is the artists' own work in the collage.

**One open question, for whenever this gets built:** what wins when an artist's colours and
their site's declared palette disagree. The editor already has a drift-and-rebase pattern
for this shape.
